## Context

DarkFrame's authentication is **split**: game login uses a custom JWT cookie (`darkframe_session`), while API routes use `getAuthenticatedUser()`/`verifyAuth()` from `@/lib/authMiddleware` which reads **Supabase** session cookies. These are two completely different sessions. The Supabase cookie doesn't exist for players who logged in via the game — every protected route returns 401/403.

This was partially masked during the MongoDB→Supabase migration because the migration team never tested routes end-to-end with a game-logged-in user.

**Impact:** The admin panel, beer bases, banking, shrine, combat, WMD, auction house, clan management, friends system, chat editing, player stats, and 37+ other features are **all non-functional** for the player.

### Root Cause

```typescript
// lib/authMiddleware.ts:120-139
export async function getAuthenticatedUser() {
  const supabase = createServerClient();  // reads cookies from request
  const { data: { user } } = await supabase.auth.getUser();
  if (!user) return null;  // ← ALWAYS null for game-session users
  // ...
}
```

Every protected route calls this function, gets `null` because Supabase cookies don't exist, and gates the request with 401/403.

---

## Fix Plan

### Strategy: PHP-Style `username` Param + Admin Lookup

All routes will switch from `getAuthenticatedUser()` → reading `username` from body (POST) or query params (GET). Admin routes will add a lightweight DB check (`SELECT is_admin, rank FROM players WHERE username = ?`).

This is the **pattern already proven** on `app/api/factory/list`, `app/api/tier/unlock`, `app/api/beer-bases`, and `app/api/admin/bot-spawn` — all working correctly.
