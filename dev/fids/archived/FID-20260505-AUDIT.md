## Context

Dual-system deep audit of the WMD (Weapons of Mass Destruction) and Clan subsystems. Player reports: (1) users unable to join/create clans, (2) WMD page in admin panel is completely blank. Full 0-EOF audit of 20+ source files across both systems revealed 10 defects — 2 CRITICAL shape mismatches in the WMD admin API, 3 HIGH-severity wiring failures, and 5 medium/low issues.

## Issue 1: WMD Admin Page Renders Blank — API Response Shape Mismatch

### Symptoms

- Admin panel WMD section shows all zero values or blank tiles
- No errors in browser console (fetch succeeds but fields are `undefined`)
- All WMD stats display as 0/empty regardless of actual data

### Root Cause Analysis

The admin page at `app/admin/page.tsx` makes two API calls:

**Call 1:** `GET /api/admin/wmd?action=status`

The admin page expects this response shape in JSX:
```
wmdStatus.activeOperations?.missiles     → data.activeOperations.missiles
wmdStatus.activeOperations?.votes        → data.activeOperations.votes  
wmdStatus.jobs?.scheduled                → data.jobs.scheduled
wmdStatus.alerts?.length                 → data.alerts[]
wmdStatus.alerts[].message               → data.alerts[].message
wmdStatus.alerts[].severity              → data.alerts[].severity
```

The API at `app/api/admin/wmd/route.ts:193-205` **actually returns**:
```json
{ "success": true, "data": { "status": "operational", "activeMissiles": N, "activeBatteries": N, "deployedSpies": N, "activeVotes": N } }
```

The returned `data` has no `activeOperations`, `jobs`, or `alerts` nesting. Every field the admin page reads is `undefined`. Since all values are guarded with `|| 0` or `|| '...'`, the page renders zeros and blank text instead of throwing errors.

**Call 2:** `GET /api/admin/wmd?action=analytics`

The admin page expects:
```
wmdAnalytics.missiles?.total            → data.missiles.total
wmdAnalytics.missiles?.intercepted      → data.missiles.intercepted
wmdAnalytics.missiles?.hit              → data.missiles.hit
wmdAnalytics.missiles?.successRate      → data.missiles.successRate
wmdAnalytics.missiles?.avgDamage        → data.missiles.avgDamage
wmdAnalytics.votes?.total               → data.votes.total
wmdAnalytics.votes?.passed              → data.votes.passed
wmdAnalytics.votes?.failed              → data.votes.failed
wmdAnalytics.votes?.approvalRate        → data.votes.approvalRate
wmdAnalytics.defense?.researchAttempts  → data.defense.researchAttempts
wmdAnalytics.defense?.researchSuccesses → data.defense.researchSuccesses
wmdAnalytics.defense?.activeSpyOps      → data.defense.activeSpyOps
wmdAnalytics.economy?.totalSpent        → data.economy.totalSpent
wmdAnalytics.economy?.avgCost           → data.economy.avgCost
wmdAnalytics.economy?.uniqueClans       → data.economy.uniqueClans
wmdAnalytics.balance?.warnings          → data.balance.warnings
```

The API at `app/api/admin/wmd/route.ts:151-165` **actually returns**:
```json
{ "success": true, "data": { "missiles": N, "defenses": N, "spies": N, "activeVotes": N, "alerts": N } }
```

The returned `data` has flat number fields, not nested object structures. Again, every field is `undefined`.

## Issue 2: WMD Analytics Service Is Dead Code

### Symptoms

- Rich analytics platform (815 lines, 5 major functions) never executes
- Admin API route does bare `count` queries instead of calling analytics functions
- GlobalWMDStats, ClanWMDActivity, MissileImpactReport, VotingPatterns, BalanceMetrics — all unreachable

### Root Cause Analysis

`lib/wmd/admin/wmdAnalyticsService.ts` exports: `getGlobalWMDStats()`, `getClanWMDActivity()`, `getMissileImpactReport()`, `getVotingPatterns()`, `getBalanceMetrics()`. The admin API route at `app/api/admin/wmd/route.ts` imports none of them. Instead it does inline supabase `count` queries that return flat numbers — a completely different (and much thinner) contract.

## Issue 3: WMD POST Actions Are Pure Stubs

### Symptoms

- Admin actions (expire vote, disarm missile, adjust cooldown, flag activity) return success without doing anything
- No database writes occur for any POST action
- Real implementations exist but are never wired

### Root Cause Analysis

`app/api/admin/wmd/route.ts:243-281` — all 4 POST actions return `{ success: true, data: {} }` with only console log output. The real implementations live in `lib/wmd/admin/wmdAdminService.ts`:

| Action | Route stub | Real implementation |
|--------|-----------|---------------------|
| `expire-vote` | line 249-250 | `forceExpireVote()` — updates vote status, logs audit, creates alert |
| `disarm-missile` | line 259-260 | `emergencyDisarmMissile()` — updates missile status, refunds 50% to clan treasury |
| `adjust-cooldown` | line 269-270 | `adjustClanCooldown()` — modifies `clan_settings.wmd_cooldown_until` on clans table |
| `flag-activity` | line 279-280 | `flagSuspiciousActivity()` — inserts into `player_flags` and `wmd_notifications` |

The route file's docstring (lines 371-373) even acknowledges: *"All service calls return stub data while WMD services are migrated from MongoDB."*

## Issue 5: `requireAuth` Maps `playerId` to Username — Naming Fracture

### Symptoms

- All clan service functions accept `playerId` parameter but it contains a username
- `clanService.ts` does `eq('username', playerId)` throughout
- `clan_members.player_id` column stores usernames, not UUIDs

### Root Cause Analysis

`lib/authMiddleware.ts:47` sets `playerId: username`. This is consistent with the Supabase schema where `players` primary key is `username` (text). The naming `playerId` is misleading — it implies a UUID. Any new developer working on clan code could introduce a UUID lookup, causing silent failures.

The clan create/join core logic functions correctly — the naming is the issue, not the logic.

## Fix Plan

### Strategy

The WMD admin API route must be reworked to:
1. Import and call the existing `wmdAnalyticsService.ts` functions for GET analytics
2. Import and call the existing `wmdAdminService.ts` functions for POST actions
3. Shape responses to match what `app/admin/page.tsx` expects (or vice versa — align page to new API shapes)

The clan `playerId` naming issue is a refactor decision: rename `playerId` → `username` throughout clan code, or leave as-is with a docstring note.

The admin page (`app/admin/page.tsx`) is the consumer that defines the contract. The API route must be rewritten to return data in the shape the admin page already expects. This avoids touching the React component (which is complex 3343-line file) and keeps blast radius on the server-side route.

## Live-Server Discovered Defects (2026-05-05)

### Issue 11: Clan Join Crash — MongoDB → Supabase Shape Mismatch

**Crash:** `TypeError: Cannot read properties of undefined (reading 'length')` at `ClanManagementView.tsx:696`
```
clan.members.length → members is not embedded in Supabase
clan.level.currentLevel → level is a number, not an object
clan._id → MongoDB relic, should be clan.id
```

**Fix:**
- `app/api/clan/search/route.ts`: Rewritten to return enriched flat objects with `memberCount`, `level`, `id` instead of raw Supabase rows with embedded nested fields from MongoDB era
- `components/clan/ClanManagementView.tsx`: Updated `JoinClanView` to use `clan.id`, `clan.level`, `clan.memberCount`, `clan.maxMembers`, `clan.territories`
- `app/api/clan/join/route.ts`: Added direct `clanId`-based join path (previously only invitation-based)
- `lib/clanService.ts`: Added `joinClanDirectly()` function for public clan membership

### Issue 12: WMD Player Panels Blank (Non-Research Tabs)

**Symptom:** Only research tab shows content (RP from game context). All other tabs render empty — API calls succeed but WMD tables may be empty or missing from database.

**Status:** Requires database verification. WMD table schema defined in `lib/db/schemas/wmd.schema.ts` but may not have been applied to Supabase. If tables don't exist, all WMD player API routes will 500 and panels render with zero data.
