## Issue 1: Inventory API Returns Raw DB Rows — Frontend Filters Silently Broken

### Symptoms

- Inventory page "Diggers" filter tab shows empty results
- Inventory page "Tradeable" filter tab shows empty results
- `inventory.diggers.common/.rare/.legendary` counts all `undefined`

### Root Cause Analysis

**`app/api/inventory/route.ts:54`** returns:
```json
{ "success": true, "inventory": { "items": [raw player_inventory rows] } }
```

The raw rows have `item_type` (values: `METAL_DIGGER`, `ENERGY_DIGGER`, `UNIVERSAL_DIGGER`, `TRADEABLE_ITEM`) and snake_case fields. The frontend at `app/game/inventory/page.tsx:143-147` filters by:
```javascript
filtered.filter(item => item.category === 'digger')
filtered.filter(item => item.category === 'tradeable')
```

The `category` field does not exist on raw DB rows. Every filter returns `[]`. Additionally, `inventory.diggers.common/.rare/.epic/.legendary` are never populated by the API — all counts render as blank/`undefined`, and the bonus calculation at lines 170-175 produces `NaN`.

## Issue 2: Digger Bonus Always Flat +5% — Diminishing Returns Never Applied

### Symptoms

- 100 Metal Diggers gives +500% gathering bonus instead of intended ~+85%
- Players rapidly out-scale the economy with unchecked digger stacking

### Root Cause Analysis

**`lib/caveItemService.ts:81-88`** unconditionally adds `bonus (5)` to `gathering_metal_bonus` or `gathering_energy_bonus`:
```typescript
const bonus = item.bonusPercent || 5;
if (item.type === ItemType.MetalDigger || item.type === ItemType.UniversalDigger) {
    metalBonus += bonus;
}
```

The `GAME_CONSTANTS.DIGGER_TIERS` spec at `types/game.types.ts:735-741` defines:
```
First 10: +2% each  (max +20%)
Next 20:  +1% each  (max +20% more)
Next 40:  +0.5% each (max +20% more)
Next 80:  +0.25% each (max +20% more)
After 150: +0.1% each
```

This tiered formula is never computed or applied. The `bonusPercent` should be calculated dynamically based on the player's current digger count, not hardcoded to 5.

## Issue 3: Tradeable Item Naming Inconsistent — Plus All Names Are Generic

### Symptoms

- All Metal Diggers display as "Metal Digger" regardless of rarity
- All Energy Diggers display as "Energy Digger" regardless of rarity  
- All Universal Diggers display as "Universal Digger" regardless of rarity
- All Tradeable Items display as "Ancient Relic" or "Tradeable Item"
- No variety — 4 hardcoded names for the entire loot table

### Root Cause Analysis

**`lib/itemUtils.ts:10-15`** — `ITEM_NAMES` is a flat 4-entry map with one name per item type. `ITEM_EFFECTS` is similarly flat. There is no rarity tiering, no name pool, no randomization. Every item of the same type gets the identical name.

**`lib/caveItemService.ts:27-38`** — `generateCaveItem()` picks a type and rarity, then assigns the flat name from `ITEM_NAMES[itemType]`. Rarity has zero influence on the name, description, or value.

The design intent was a tiered loot table like other MMOs (e.g., "Rusty Shovel" → "Iron Pick" → "Titanium Drill") where rarity tier visibly distinguishes the item. The current system has all diggers at Common with identical names, making every find feel identical.

### Required Design: Tiered Name Pools

Each `ItemType × Rarity` combination needs a pool of names. On item generation, a name is randomly selected from the appropriate pool.

| ItemType | Common | Uncommon | Rare | Epic | Legendary |
|----------|--------|----------|------|------|-----------|
| **Metal Digger** | Rusty Shovel, Bent Crowbar, Worn Pick | Iron Pick, Steel Spade, Heavy Drill | Titanium Excavator, Plasma Cutter, Diamond Bit | Quantum Auger, Mole Machine, Seismic Borer | World Eater, Core Drill, Planet Cracker |
| **Energy Digger** | Copper Coil, Tin Capacitor, Old Battery | Silver Conduit, Crystal Diode, Pulse Cell | Gold Transformer, Arc Reactor, Ion Collector | Plasma Dynamo, Tesla Core, Lightning Rod | Void Heart, Singularity Battery, Dyson Shard |
| **Universal Digger** | Broken Compass, Rusty Detector, Old Scanner | Surveyor's Kit, Geo-Probe, Alloy Finder | Terrain Scanner, Element Mapper, Pulse Seeker | Omni-Extractor, Matter Sweeper, Phase Harvester | Gaia Engine, Reality Drill, Creation Spike |
| **Tradeable Item** | Rusty Gear, Torn Map, Old Battery, Bent Key, Scrap Metal | War Medal, Ancient Coin, Data Slate, Ivory Figurine, Silver Ring | Pulse Crystal, Precursor Artifact, Energy Cell, Gold Ingot, Star Chart | Titan Circuit, Dark Matter Shard, Phoenix Feather, Chrono Lens, Void Pearl | Star Core Fragment, Omega Relic, Creation Seed, Eternity Prism, God's Tear |

Each pool should have 3-5 entries. The generated name is stored in `player_inventory.name` at creation time and displayed as-is (no normalization needed for new items). Legacy items with generic names are normalized to `<Rarity> <ItemType>` format (e.g., "Common Metal Digger").

## Issue 4: Inventory API Never Uses `normalizeItemRow`

### Symptoms

- Raw snake_case data delivered to frontend
- `item_type` delivered as `METAL_DIGGER` instead of `'Metal Digger'`
- Descriptions missing from inventory display

### Root Cause Analysis

**`lib/itemUtils.ts:33-54`** — `normalizeItemRow()` was created specifically to convert raw DB rows into frontend-ready display objects with clean names, types, and descriptions. **No API route imports or calls it.** The function exists but is dead code. The inventory route at `app/api/inventory/route.ts` returns raw rows directly. The `app/api/player/inventory/route.ts` also returns raw rows.

---

## Issue 5: `harvestService.test.ts` Tests Nonexistent Code

### Symptoms

- Tests pass against a diminishing returns formula that isn't applied
- Creates false confidence that digger bonuses are properly balanced

### Root Cause Analysis

**`lib/harvestService.test.ts:258-294`** — Multiple test cases validate the formula `baseBonus * count * (1 - count/20)`. This formula is never invoked in `caveItemService.ts` or `harvestService.ts`. The actual bonus is a flat sum, not a diminishing product.

### Approach

The fix ties these together via `caveItemService.ts`:
1. At digger collection time, compute the correct `bonusPercent` from `DIGGER_TIERS` based on current digger count
2. Apply that computed bonus (not hardcoded 5) to the player's gathering bonus
3. Store the applied bonus as the item's `bonusPercent` field

Then `normalizeItemRow()` in the API route adds `category: isDigger ? 'digger' : 'tradeable'` and `gatheringBonus: item.bonusPercent`.
