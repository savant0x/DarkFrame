## Remaining Work (All Sources Consolidated)

### Item 1: Auth — Fix Double-Auth Gap (from FID-20260505-AUTH)

**Problem:** Game login stores a custom JWT in `darkframe_session` cookie. API routes use `requireAuth()` which reads Supabase's `sb-*-auth-token` cookie via `supabase.auth.getUser()`. These are two completely different sessions. A player who logs in via `/api/auth/login` has a `darkframe_session` cookie but NO Supabase cookie — every `requireAuth()` call returns 401.

**Scope:** 52 files, 85+ endpoints

**Fix:** Make `resolveAuth()` in `authMiddleware.ts` read the `darkframe_session` cookie as its primary auth source. Decode the JWT, extract username, look up player. Only fall back to Supabase session if no `darkframe_session` exists.

**Files:** `lib/authMiddleware.ts` (resolveAuth function)

### Item 2: Bot Spawning Refactor (from FID-20260504-PHASE7)

**Problem:** `POST /api/admin/bot-spawn` returns 501. `POST /api/admin/bot-regen` returns 501. Bot spawning backend references MongoDB patterns.

**Fix:** Refactor `lib/botService.ts` for Supabase batch inserts. Wire the admin routes to call real bot service functions. Remove 501 stubs.

**Files:** `lib/botService.ts`, `app/api/admin/bot-spawn/route.ts`, `app/api/admin/bot-regen/route.ts`

### Item 3: WMD Admin POST Wiring (from FID-20260504-ADMIN Item 5)

**Problem:** WMD admin POST actions (launch control, disarm, adjust-cooldown, flag-activity) were already wired in FID-20260505-AUDIT to `wmdAdminService.ts`. Verifying these work end-to-end with real data.

**Status:** Code is written. Needs live verification that WMD tables contain data and services execute correctly.

**Files:** `app/api/admin/wmd/route.ts` (already fixed), `lib/wmd/admin/wmdAdminService.ts` (already implemented)

### Item 4: Player Sessions Table (from FID-20260504-PHASE7)

**Problem:** `player_sessions` table doesn't exist in Supabase. The admin session tracking routes return empty arrays. No session analytics available.

**Fix:** Create SQL migration for `player_sessions` table. Create player session tracking service that records login/logout events. Wire admin session routes to query real data.

**Files:** `supabase/migrations/`, `lib/sessionTrackingService.ts`, `app/api/admin/player-tracking/sessions/route.ts`

### Item 5: `is_banned` Column + Ban Enforcement (from FID-20260504-PHASE7)

**Problem:** Admin can "ban" a player but there's no `is_banned` column on the `players` table to enforce it. Ban/unban buttons write to `admin_logs` only.

**Fix:** Add `is_banned boolean not null default false` column to `players` table via migration. Add ban check to `resolveAuth()` in `authMiddleware.ts` — if player is banned, return 403.

**Files:** `supabase/migrations/`, `lib/authMiddleware.ts`

### Item 6: Predictive Beer Base Spawning (from FID-20260504-PHASE7)

**Fix:** Create predictive spawning recalculation endpoint that queries player activity data and computes spawn forecasts.
