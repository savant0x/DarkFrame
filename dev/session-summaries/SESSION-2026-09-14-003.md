## Design decisions

- **Claim arbitration via `findOneAndUpdate`** (not `updateOne` match counts): the shim's
  `updateOne` returns `modifiedCount: 1` unconditionally; `findOneAndUpdate` returns null
  on a missed match, which is an honest claim signal. Escrow releases are then gated by
  the claim (exactly-once) and by pair filters where the releasing write could race a
  state change.
- **Leader refund from a FRESH post-claim re-read**: a concurrent placeBid may have
  become leader after the buyer's initial findOne; the fresh leader is the one whose
  escrow is actually held.
- **Leader-is-buyer diff charging**: the leader's escrow IS the payment → charge
  `buyoutPrice − currentBid`, never a full charge plus self-refund (the pre-FID behavior
  would double-pay or forfeit in every interleaving).
- **Unit escrow by snapshot + array rebuild**: the `$pull` probe proved `$pull` SQL is
  dead on this engine, so no removal path uses it. The snapshot makes delivery and
  refunds independent of seller-side state (a seller who rebuilt their army cannot
  break delivery), and the route's zod schema stripping unknown fields means a
  client cannot forge a snapshot — the service owns it.
- **Legacy-listing fallback**: pre-escrow rows (no `unitSnapshot`) keep working via
  seller-side lookup + `$set` rebuild at transfer.

2. **The listing fee-merge dropped `$set`**: the FID-065-era merge fixed an `$inc`
   overwrite but carried only `$inc` — the unit escrow's `$set: { units: … }` was
   silently dropped (finding 6's failure mode reborn inside the fix). Caught by the new
