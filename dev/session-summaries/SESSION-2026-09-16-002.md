# SESSION-2026-09-16-002 — Protocol amendment: `converged` → `loop-complete` (status vocabulary fix)

**Date:** 2026-09-16 · **Protocol:** ECHO v0.1.2 single-agent · **Branch:** `main` (direct push)
**Operator finding:** the status name `converged` was breaking comprehension — "it's implying
that code was done and that's a completely separate approval step."

## Root cause (established before editing)

- The protocol's own Vocabulary already defined the loop as running ONLY on the FID document
  ("the iterative fix/verify cycle that runs on the FID document — not the code"). The status
  label violated its own semantics by attaching the loop's mathematical convergence to the
  FID's overall status, reading as a code claim.
- The FSM compounded it: the `COMPLETE` state row said "Close FID. Move to archive. Update
  CHANGELOG." at the plan-only point — merging end-of-plan into closure and mechanically
  producing archived `converged` FIDs with full implementation records (the exact drift the
  2026-09-16 ground-truth sweep spent the day correcting: 4 stale fields, 15+ off-list status
  strings).

## Operator decision (after two rejected candidates)

- `approved` REJECTED — "a plan can not be approved until the FULL perfection loop has been
  completed"; approval is the separate implementation step, so the name would re-create the
  same ambiguity.
- Resolution: **`loop-complete`** — "loop complete, pending implementation." The status says
  what happened to the DOCUMENT; implementation and its approval remain completely separate.
