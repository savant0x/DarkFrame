## Intent (logged before implementation — Law 8)

Audit the entire factory-attack flow end to end against live evidence rather than code
reading alone, identify why attacks "always" fail with zeroed numbers, fix what is actually
broken, and prove each suspicion healthy or broken with an experiment. No speculative
rebalances.

## Audit chain (scratch experiment scripts deleted after use; evidence preserved)

1. Call path: `TileRenderer` ATTACK → `handleAttack` → `POST /api/factory/attack` →
   session auth → presence + flag-bearer gates → `attackFactory` (`lib/factoryService`).
2. Server log: three real POSTs from the operator's session — two rolls logged
   `Power: 2272610 vs Defense: 1000` (both missed), third POST = cooldown rejection.
3. Factory rows: `last_attacked_by='fame'` on two L1 wild factories; fame owns 0 factories;
   three bot-owned factories prove the capture path works historically.
4. Live experiment A (fresh account, power 50,110 vs 1,000): **captured on the first roll**
   — the 90% mechanic works through the real HTTP route.
5. Live experiment B (weak attacker 110 vs 1,000 → 11% chance): 2/2 genuine misses returned
   `playerPower=110, factoryDefense=1000` — real numbers in failure payloads.
6. Root cause of the display: the client's failure branch (FID-20260911-041 mapping)
   hardcodes `playerPower: 0, factoryDefense: 0` for every failure shape — combat miss,
   cooldown, presence 403 all identical 0/0. The operator's "always fails at 0/0" =
   unlucky double-miss (1%) + cooldown lockout + an opaque readout.

Cleared suspicions (evidence): position persistence (moves write `current_position_*`),
zero-power math (2.27M computed), legacy units-collection dependence (flow reads
`totalStrength`), `Math.random` tampering (repo grep clean).

## Fix shipped (app/game/page.tsx — both handlers)

Factory `handleAttack`: failure branch preserves `data.playerPower`/`data.factoryDefense`
when numeric (rejections legitimately carry none → 0). Base-raid `handleBaseAttack`:
failure branch mirrors the success path's `data.battle?.attacker/defender?.damageDealt`
extraction. Verbatim rejection messages (FID-041) unchanged. After the fix, a genuine miss
reads e.g. "Your Power: 2,272,610 · Factory Defense: 1,000" instead of 0/0.
