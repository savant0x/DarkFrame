## Intent (logged before implementation — Law 8)

1. **Routing decision (recorded before code):** simple-task flow, not a FID. The change is ~15 lines across two source files plus a pin test — no new APIs, no novel architecture, no verification-failure trigger; far below every complex-task trigger in `task_routing`. A FID would add process cost without adding information the row + this record do not already carry.
2. **Design (and why it is not page-only):** the directive's literal fix — make the page's `complete` handler render `event.message` — is necessary but not sufficient. The engine emits `complete` **twice** on a natural map completion: `processNextTile` announces `'Entire map completed!'` (no data), then the bookkeeping `stop()` emits a second `complete` **with** the final stats carrying the message `'Auto-farm stopped'`. A page-only fix would make the second, stats-carrying event **overwrite the honest completion label with "stopped"** — the mirror image of the defect. Five Questions #1 ("will this work for ALL cases?") fails for the page-only variant, and the protocol mandates redesign until all answers are yes. The redesign follows the repo's own row-131 lesson (fix at derivation): `stop(reason: 'manual' | 'map-complete' = 'manual')` states its cause, and the page renders the event's own message verbatim.
3. **Approved scope (this item only):** engine `stop()` reason parameter + message selection; the one internal call site (`processNextTile`) passes `'map-complete'`; the page's `complete` branch reads `event.message`; a pin test for the engine's two stop messages (red-drilled against the pre-fix engine); the one-line `dev/architecture.md:2025` doc example that teaches the exact hardcoding anti-pattern row 133 outlaws. Nothing else. `destroy()` keeps the default `'manual'` reason — a logout/unmount cleanup genuinely is a stop, and its announcement becomes *more* honest than today's "Map completed!".
4. **Not in scope, recorded rather than touched:** the `AutoFarmPanel` line-165 display rule (`{isActive ? lastAction : 'Paused'}` — after any stop the lastAction line is unreadable until the next active session; adjacent to row 130's open viewport-chip sub-item, same surface, pre-existing). The double-`complete` emission itself is *kept*: the 005 merge contract ("only stop() emits `complete` WITH the final stats; the map-completion event carries no data") depends on it, and after this fix both emissions agree with reality.
