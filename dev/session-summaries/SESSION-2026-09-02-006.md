## Intent (logged before implementation — Law 8)

### Diagnosis (bounded probe of just the friends dirs — completed despite the 300s wall)

The full-suite failure mode is **not a plain hang**: the run dies in a **JavaScript heap OOM crash**
(`Ineffective mark-compacts near heap limit`) after `AddFriendModal` burned ~55s in stuck tests. 29 failures
decompose into 4 mechanisms:

| Class | Suite(s) | Mechanism (evidence) | Fix |
| ----- | -------- | -------------------- | --- |
| A | AddFriendModal (12 × ~5000ms) | `vi.useFakeTimers()` active while raw `userEvent.type/click` awaits internal timers → stalls to the 5s cap. 3 render-only tests pass (33ms/2ms/4ms) | user-event timer bridge: `userEvent.setup({ advanceTimers: vi.advanceTimersByTime })` |
| B | FriendRequestsPanel (14, fast) | `vi.runAllTimersAsync()` called with **no** fake timers: "timers APIs are not mocked" (log lines 4/29–14/29) | enable `vi.useFakeTimers()` + bridge; bounded `advanceTimersByTimeAsync(0)` instead of unbounded `runAllTimersAsync` (component has a 5s `setInterval` — line 125) |
| C | FriendsList (2 fail + others) | ambiguous `/VIP/i` matches username `vipFriend` AND badge `VIP` (multiple-elements error, log 2/29); one click timeout to re-diagnose empirically; component polls status every 2s (line 162) | exact-text `getByText('VIP')`; empirical re-run for the click timeout |
| D | friends.integration (1, fast) | `beforeEach` runs `deleteMany` through the compat layer against the **real configured `DATABASE_URL`** (`SASL: client password must be a string` — the only thing that saved the dev DB). The "live Mongo" premise is structurally dead post-pivot; route handlers are pure drizzle (`friendService` has zero compat-layer calls) | skip-gate behind explicit `RUN_LIVE_DB_TESTS=1` opt-in, prominently documented — tests must never silently target a real DB |

Plus a dead-weight discovery: `vitest.setup.ts` boots a **real in-memory MongoDB per worker** (5 mongod
spawns per run observed) that **nothing consumes** — runtime reads `DATABASE_URL` via the compat layer;
`MONGODB_URI` consumers in src are ops scripts only. OOM kindling. Fix: gate behind
`TEST_MONGO_MEMORY=1` (default off), keep TextEncoder/matchMedia/JWT_SECRET setup.

> **⚠️ Root-cause supersession (end-of-session):** the class table above records the *initial* per-suite
> hypotheses. The decisive diagnostic (throwaway probe file, 3 trivial components under fake timers) proved
> the dominant mechanisms were **environment-level**, not per-test: (1) `IS_REACT_ACT_ENVIRONMENT` was never
> set — RTL only auto-sets it under jest — so React 18's concurrent scheduler never flushed inside `act()`
> (empty `<body/>` renders, user-event never settling); (2) `@testing-library/dom@10.4.1`'s
> `jestFakeTimersAreEnabled()` hard-checks `typeof jest` **before** its sinon-clock check, so RTL `waitFor`
> never advanced vitest fake timers (frozen interval → every waitFor burned the 5s cap). Both fixed in
> `vitest.setup.ts` (act flag + minimal documented `jest` timer shim); the per-suite timer bridges remain
> correct and necessary on top. FriendsList's click hang had an additional **production** cause — see Changes.

## Changes

**Test environment (`vitest.setup.ts`):**
1. `IS_REACT_ACT_ENVIRONMENT = true` declared (React 18 + vitest requirement; fixes act flushing).
2. Minimal `jest` global shim delegating only RTL-called timer methods (`advanceTimersByTime`,
   `advanceTimersByTimeAsync`, `runAllTimers`, `runAllTimersAsync`, `clearAllTimers`) to `vi` — makes RTL
   `waitFor` advance vitest fake timers. Nothing else emulated; documented in place.
3. Per-worker in-memory MongoDB gated behind `TEST_MONGO_MEMORY=1` (default off — zero consumers; OOM kindling).

**Suites (timer bridging + honest fixes):**
4. `AddFriendModal.test.tsx` — `userEvent.setup({ advanceTimers: vi.advanceTimersByTime })`; exact-text
   `getByText('VIP')` / `getByText('Pending')` (regexes matched usernames); message-cap test asserts the
   `maxLength="200"` attribute (jsdom does not enforce maxLength while typing); close-reset test flushes the
   reset effect via `advanceTimersByTimeAsync(0)`.
5. `FriendRequestsPanel.test.tsx` — fake timers enabled; bounded `advanceTimersByTimeAsync(0)` in
   `renderAndWait` instead of unbounded `runAllTimersAsync` against the 5s poll interval; bridged user-event.
6. `FriendsList.test.tsx` — refresh test asserts friends-list fetches by URL (component legitimately fires
   one online-status fetch on mount; bare counts raced the poller).
7. `friends.integration.test.ts` — skip-gated behind `RUN_LIVE_DB_TESTS=1` with prominent header warning:
   its `beforeEach` wipes `players`/`friends` in whatever `DATABASE_URL` targets. Mock conversion was the
   original plan; the gate is the honest fix (mocking would fake-test dead code). **Schema amendment vs. the
   logged intent — recorded explicitly, not absorbed.**

**Production code (two real bugs — stabilization was impossible without them):**
8. `components/friends/FriendsList.tsx` — polling-churn fix: `fetchOnlineStatus` had `[friends]` closure in
   the interval effect deps, so every status update recreated the callback, tore down the interval, and
   refetched immediately (polling never ran on its 2s cadence; the fetch/render loop starved test
   macrotasks and caused the click-test hang). Now ref-stable (`friendsRef`), interval created once.
9. `components/friends/AddFriendModal.tsx` — close-reset effect: prop-driven closes never ran `handleClose`,
   so search results/message leaked into the next open.

**Cosmetic residue (documented, zero test impact):** RTL still emits "act environment" toggle warnings in
multi-file runs — its `asyncWrapper` toggles the flag around waits and a jest/vitest detection gap makes the
warning fire while tests pass.
