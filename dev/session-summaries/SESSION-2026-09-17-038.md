**Date:** 2026-09-17 · **Protocol:** ECHO v0.1.2 single-agent (16 laws) · **Branch:** `main`
**Operator directive:** migrate the deprecated Next.js middleware file convention to
proxy, as the boot smoke's codemod warning suggested.

## Ground truth (before any edit)

- `middleware.ts` at repo root, convention-loaded — **zero importers** (reference census:
  the only `middleware` grep hits are the unrelated `lib/authMiddleware.ts` API helper and
  `lib/middleware/` request-chaining barrel; next.config has no mentions).
- History irony: the file header records it was renamed **from** `proxy.ts` **to**
  `middleware.ts` on 2026-04-03 — the old rename predates Next 16 flipping the
  convention back to proxy.
- Convention contract verified from the installed build (`node_modules/next/dist/build/index.js`
  warns exactly: *middleware file convention is deprecated… `npx @next/codemod@canary
  middleware-to-proxy .`*) and the official doc page nextjs.org/docs/messages/middleware-to-proxy:
  rename file + rename export `middleware` → `proxy`; `config` unchanged **per the doc**.

## What shipped

- `middleware.ts` → `proxy.ts` (`git mv`, rename preserved) + export renamed to
  `export async function proxy(request: NextRequest)`; prose updated; a rename-history
  note records both directions of the file's naming travel.

## The smoke-earned finding (doc gap)

- The doc says "config unchanged," but booting the migrated file surfaced a hard error:
  **`Route segment config is not allowed in Proxy file at "./proxy.ts". Proxy always
  runs on Node.js runtime.`** The proxy convention **forbids** `config.runtime` —
  the old `runtime: 'nodejs'` opt-in (which existed precisely because Edge was
  deprecated and its bundler rejected the `@/lib` imports) is now both unnecessary
  and illegal. Removed with a comment explaining why. This is a real convention
  contract change the codemod and doc page do not advertise; without the boot smoke
  it would have broken the next dev-server start.
