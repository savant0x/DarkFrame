## The error worth recording

The audit initially reported that **SCOPE rows 134/135 carried each other's dispositions** — "the ledger currently lies about an open item." That was false. My probe split each table row on `|` and read a fixed column index; row 134's description embeds an escaped `\|` (the text `1 failed | 1338 passed (1339)`), giving the row six pipes instead of four, so the column index silently shifted onto the next row's content. Verified by counting pipes on the raw line. **The ledger rows were correct all along.**

The lesson is the one this repo keeps re-learning in new forms: a probe that mis-indexes does not announce itself — it returns plausible text. The three structural defects that *were* real (duplicate `[OPEN-OUT-OF-SCOPE]` header, the 26/27/28 numbering gap, two stale-unchecked boxes) were each confirmed by reading the raw lines, not by column arithmetic.
