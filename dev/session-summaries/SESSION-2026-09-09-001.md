## FID-026 §7 follow-up CLOSED — prerender `location is not defined` (2026-09-09)

- **Root cause (the misleading part):** the error stack pointed at `.next/server/chunks/8972.js:1:1265` in the referrals page render, but that chunk contained **zero** `location` tokens — because the module-scope variable in the built code was named `l`, not `location`. Col 1265 decoded (by exact byte offset) to the minified ternary `(l.push("/login"), null)` inside component `k`: **`router.push('/login')` called during render** in `app/referrals/page.tsx`. During static prerender the app router's navigation internals read `location`, which is undefined server-side → ReferenceError → Next silently falls back to client rendering for the page.
- **Fix:** redirect moved to `useEffect` with the `!isLoading && !player` guard (the pattern every other auth-gated page uses; the guard matters because `player` stays null until GameContext's async session check completes) + `return null` render gate. `useEffect` import added.
- **Census:** referrals was the only page with a render-body redirect — all 8 other `router.push('/login')` sites were already effect-scoped.
- **Verification:** fresh `next build` logs **0** `location` errors (previously 1 per build), exit 0, 238/238 pages; referrals now actually prerenders. Gates: tsc 0 · eslint 0 errors (2 pre-existing warnings) · vitest 387 passed / 1 skipped.
- **Records:** FID-20260909-025 §7 known-issue struck through with resolution note.
