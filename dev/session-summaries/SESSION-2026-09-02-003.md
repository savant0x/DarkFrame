## Intent (logged before implementation — Law 8)

`npm run lint` = `next lint`, which Next.js 16 removed — the script fails outright (`no such directory:
...\lint`), so no lint gate exists. The repair restores the gate with minimal, install-free changes.

Design (GREEN — documented before code):

1. **`package.json`:** `"lint": "next lint"` → `"lint": "eslint ."`.
2. **`.eslintrc.json`:** `next lint` auto-injected TypeScript parser/plugin support when it detected a TS
   project; the bare ESLint CLI does not. `extends` gains `"next/typescript"` (shipped by the installed
   eslint-config-next 15.0.2) to replicate that behavior. Alternative considered — flat config
   (`eslint.config.mjs`) — rejected: requires eslint 9 for first-class flat support and a rewrite; the
   eslintrc format works on the installed eslint 8.57.1 with a one-line change (minimal-change principle).
3. **`.eslintignore`:** `.next/`, `out/`, and `nul`. Rationale for `nul`: Windows reserved-name artifact in
   the repo root already breaks ripgrep's directory walk (observed: `os error 1`); ESLint's traversal must
   not hit it. (`node_modules`/`.git` are ignored by ESLint by default.)
4. **Verification (double audit):** Method 1 — run `npm run lint` fresh, record exit code and finding
   counts as the new baseline (a red gate that *runs* is success; findings are honest signal, not failure
   of this task). Method 2 — negative test: create a controlled violating file, confirm the gate exits
   nonzero with the expected rule, delete it.
5. **Docs:** `progress.md`, `issues.md` (B2), `QUICK_START.md` were refreshed yesterday and must not go
   stale again — minimal edits to reflect "gate functional, baseline = N findings".

Constraints: no package installs (verified: `@typescript-eslint/parser` 8.58.0 and plugin present as
eslint-config-next dependencies); no findings remediation; DB work untouched.
