   not clean — the old exit-0-on-unparsed would have been a gate hole).
   Tagged-template fetches (`fetch(String.raw`...`)`) now land in UNPARSED.
   False positives are retired via documented WAIVERS in the script, never by
   weakening the exit contract.

## Drill-hardening incidents (both caught by the drills, not by review)

1. **Regex blindness:** the drill file `fetch(String.raw`…`)` was never harvested
   at all (`CALL_RE` only matched a bare backtick after `(`) — drill expected
   exit 1, got 0. Fixed the regex to admit `[\w$.]*` before the backtick.
2. **Unreachable branch:** first fix parked tagged forms *inside*
   `if (raw.startsWith('`'))` — unreachable for tagged templates, which fell to
   the quoted-string branch and produced a garbled MISSING line (`tring.raw`…).
   Restructured to an index-based trichotomy (`backtickIdx > 0` → UNPARSED,
   `=== 0` → template parse, else quoted string).
3. Cosmetic str_replace slip removed one sentinel-comment line; repaired with the
   branch restructure.
