## 1. Ground truth before any edit

Fresh live sweep re-sized the batch-2 surface: **9 files** with live `clientPromise` usage —
6 of them (friends, friends/search, dm, dm/[id], dm/[id]/read) were **pure connection
theater** (`_db` assigned, never used; real work already on pg services), only **4** were
real rewrites (ban-player, clear-flags, logs/cleanup, player/build-unit).

Key schema/behavior facts probed before writing:
- The shim maps `'resources.metal'` → `resourcesMetal` (lib/mongodb.ts:173), so build-unit's
  `$inc` **was really charging** flat columns — the rewrite preserves the semantics as SQL
  deltas, it does not "invent" charging.
- `bans.id` is a 24-char PK **with no default**; `bans.createdAt`/`mod_log.createdAt` are
  NOT NULL with no default → the drizzle insert must generate/supply them.
- `player_flags` has **no resolvedBy/resolvedAt/adminNotes columns** — ban-player's
  autoResolve `$set` mapped to nothing (silent no-op class); only `resolved` flipped.
- `players` has **no unbannedAt/unbannedBy** — unban's `$set` mapped to nothing.
- `player_activity` has **no category column** — the ActionLog activity/admin retention
  split cannot survive; the real deleter (`cleanupOldLogs`) uses a single cutoff.
- `adminLogs` is an unmapped shim name → both admin routes' audit rows matched nothing.
  **D1: `mod_log` is the audit home** (already shaped, used by every other admin surface).
- Factories schema says `investedMetal/investedEnergy` are "maintained at write time by
  build-unit" — the Mongo path never wrote them. **D3: the pg rewrite adds the delta
  write**, matching the factory variant's FID-20260909-032 contract.
- The shim's `|| 20` slots fallback is dead on pg (`slots` is NOT NULL default 0).
