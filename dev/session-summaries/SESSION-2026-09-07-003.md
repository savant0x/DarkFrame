## 4. Verification evidence

**Diagnosis — redis.test.ts (12/16 failures, root cause: test-environment determinism):**
- Operator's shell exports `REDIS_URL=redis://localhost:6379` (echo verified); `vitest.setup.ts` does not
  clear it (grep verified) — tests inherit it (same leak class as SCOPE #23's `PORT=0`).
- `lib/redis.ts` computes `REDIS_ENABLED = !!REDIS_URL` at module load → `true` in the test run.
- The suite's ioredis mock: `Redis.prototype.incr = vi.fn()` (no implementation → `undefined`),
  `Redis.prototype.status = 'ready'` → `getRedisClient()` returns a "ready" mock.
- `check()` therefore skips the in-memory fallback and evaluates `current <= maxRequests` with
  `current = undefined` → **always `false`**.
- Proof by failure shape: the 4 passing tests are exactly those expecting `false` (block-over-limit,
  `maxRequests=0`, speed, config-shape) — vacuous passes; all 12 asserting `true`/cooldown fail. The
  suite's declared intent ("in-memory fallback is NOT mocked — real implementation") was defeated
  because the fallback path was unreachable. Explains the regression vs session 006's green run:
  `REDIS_URL` entered the test env after 2026-09-02 (SCOPE #13 era).

**Diagnosis — flagHolderSurvival.test.ts TS2345 at (87,22):**
- Line 87 = `setTableNameResolver(getTableName)`; fake's resolver typed `(t: unknown) => string`;
  drizzle's `getTableName<T extends Table>(table: T): T['_']['name']` (node_modules signature checked)
  is not assignable — contravariance (`unknown` not assignable to `Table`). Runtime: none — suite
  passes 3/3; compile-error only. Honest typing: the fake only ever receives drizzle tables → `Table`.

**Remediation (operator-approved, test-only):**
- Fix A: `vi.hoisted(() => { process.env.REDIS_URL = 'disabled'; process.env.UPSTASH_REDIS_REST_URL = ''; })`
  at the top of `lib/__tests__/redis.test.ts` — runs before module evaluation so `REDIS_ENABLED` computes
  `false`; in-file comment documents the rationale.
- Fix B: `__tests__/lib/flagHolderSurvival.test.ts` — `import type { Table } from 'drizzle-orm'`; retyped
  `tableName`, `from`, `update`, `delete`, `insert`, and the `setTableNameResolver` setter. First pass
  missed the setter (tsc error moved to (90,22) — caught and fixed; no oscillation).
