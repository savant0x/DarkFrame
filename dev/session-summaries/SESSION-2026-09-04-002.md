## Root cause

`createFlagBot` (`lib/flagBotService.ts`) inserted `createBotPlayer`'s domain-shaped object directly
via `db.insert(players).values(... as any)`:

- `isBot: true` (boolean) into `is_bot smallint` → pg rejects `true` → `Failed to create flag bot` at
  boot (the direct drizzle insert bypasses the Mongo-compat shim's boolean coercion).
- Even had the boolean passed, the nested `base`/`currentPosition`/`resources`/`bank` fields would
  have silently dropped (no such columns).

Same disease present in `botSummoningService.summonBots` (5-bot bulk insert).

## Fixes

1. **Canonical inverse mapper** — `mapDomainPlayerToRow` added to `lib/playerService.ts` (Law 13:
   single mapping path, the inverse of `mapRowToPlayer`). Handles nested→flat fields, numeric-string
   columns, smallint booleans (`isBot/isSpecialBase/isAdmin/vip` → 1/0).
2. **`createFlagBot` insert** routed through the mapper; return value now re-read via
   `getPlayerByUsername` (single read path, verifies persistence).
3. **`botSummoningService` bulk insert** routed through the mapper (`botsToInsert.map(mapDomainPlayerToRow)`).
4. **`flags.id` overflow** — `crypto.randomUUID()` (36 chars) into `varchar(24)`; replaced with the
   project's `generateId()` (would have been the *next* boot failure).
5. **`getFlagBot` phantom read shape** — expected `currentHolder` to be an object with `botId`;
   every writer stores a plain username string. The read path had never worked (always null).
   Now resolves holder by username and returns the bot only when `isBot` (null → player holds flag,
   matching the manager job's contract).
6. **Raw-row casts** in `moveFlagBot`/`handleFlagBotDefeat` replaced with `mapRowToPlayer` (no more
   `as unknown as Player` seams in the flag flow).
7. Pre-existing lint debt in all touched files cleared (unused imports/vars, `any`s → typed shapes).
