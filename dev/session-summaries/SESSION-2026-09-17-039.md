# SESSION-2026-09-17-039 — outputFileTracingRoot pinned: home-dir lockfile warning silenced

**Date:** 2026-09-17 · **Protocol:** ECHO v0.1.2 single-agent (16 laws) · **Branch:** `main`
**Operator directive:** set `outputFileTracingRoot` in next.config.js to silence the
package-lock warning the boot smoke surfaced.

## Root cause (verified, not guessed)

- Stray `package.json` (Aug 4) + `package-lock.json` (Aug 12) sit in `C:\Users\spenc` —
  an accidental home-dir npm install by some earlier tool. Next's workspace-root
  inference walks up from the project, finds two lockfiles, and warns it ignored the
  home-dir one ("would include your home directory").
- Mechanics read from installed next@16.3.5 source: `lib/find-root.js`
  (`warnRootBoundary` / `warnDuplicatedLockFiles`, mode-conditional key name via
  `process.env.TURBOPACK`) and the gate in `server/config.js:832-856` —
  warnings fire only under `if (!rootDir)` where `rootDir = tracingRoot ||
  turbopackRoot`. So one explicit `outputFileTracingRoot` silences **both** warning
  variants in **both** bundler modes; the key doubles as `turbopack.root` (setting
  both to different values triggers a mismatch warning — never do that).

## What shipped

- `next.config.js`: `outputFileTracingRoot: __dirname` with a comment recording the
  cause, the source-verified silencing semantics, and the mismatch rule.
